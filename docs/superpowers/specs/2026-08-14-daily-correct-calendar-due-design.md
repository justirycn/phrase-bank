# 今日答对目标与自然日复习设计

## 背景

当前首页把“今日首次达到三日掌握门槛”作为每日目标，因此用户完成当天任务后仍可能看到 `0 / 10`。同时，到期判断使用精确时间戳：昨天晚上学习的句子要等到今天相同时间才可复习，不符合按天学习的预期。

## 目标

1. 首页主进度改为可在当天完成的“今日答对”目标。
2. 三日掌握继续严格要求同一句在三个不同的上海自然日答对，并作为独立成果展示。
3. 到期复习在所有入口和队列中统一按上海自然日判断。
4. 已有云端和本地数据立即适用新到期规则，无需迁移或改备份版本。

## 首页统计

- `今日答对`：当天 `result === "good"` 的不同 `phraseId` 数量；新句测试和到期复习都计入，同一句当天只计一次。
- 主进度显示 `今日答对数 / 每日答对目标`，达到目标后允许显示超额完成。
- `三日掌握`：当天首次拥有第三个不同上海自然日正确记录的句子数，保留现有严格定义。
- 活动摘要继续显示 `新学 N 句 · 复习 M 句`；新学表示当天首次学习数量，复习表示当天复习过的不同句子数量。
- 原“今日巩固”不再作为主成果展示，避免与“今日答对”重复。
- 首页设置项文案从“每日掌握目标”改为“每日答对目标”。底层继续复用现有正整数偏好字段，避免云端数据迁移。

## 自然日到期规则

- 使用 `Asia/Shanghai` 日历日期判断到期，不使用滚动 24 小时。
- 只要 `nextReviewAt` 所属的上海日期不晚于当前上海日期，该句就视为到期。
- 例如昨天 20:00 学习并安排 1 天后复习，今天 00:00 起即可进入到期复习。
- IndexedDB 的有界查询使用“当前上海自然日结束时刻”作为上界，因此保留索引查询效率，并让旧时间戳立即适用。
- 训练选择器与首页列表共用同一个日期判断函数，确保首页数量、按钮状态和进入后的队列一致。

## 数据流与边界

1. 训练事件继续作为统计事实来源，不新增或改写历史事件。
2. 首页汇总从当天事件计算不同答对句子数、首次三日掌握数和复习数。
3. 每日目标仍从现有应用偏好读取；设置保存逻辑和云同步协议不变。
4. 无效的 `nextReviewAt` 不视为到期，避免异常数据进入复习队列。
5. 当前存在的未完成复习会话仍优先恢复，不受新的到期列表影响。

## 测试

- 统计测试：新学与复习的 `good` 合并去重；`hard/again` 不计入今日答对；三日掌握保持独立。
- 首页测试：显示“今日答对”、可超额、独立“三日掌握”，设置文案为“每日答对目标”。
- 日期边界测试：昨天任意时间安排的复习在今天 00:00 上海时间后到期；明天的内容仍不可用；无效日期被排除。
- 仓储与集成测试：首页到期数量和实际复习队列一致，已有精确时间戳无需迁移即可按天生效。

## 不在范围内

- 不改变三日掌握、失败重置或遗忘曲线的间隔天数。
- 不改变每天最多学习 15 个新句的限制。
- 不增加数据库或备份格式版本。
- 不修改认证、账号或云端存储结构。

# iPhone Safari 发音与操作栏对齐修复

## 目标

在不引入付费云语音服务、不改变复习排程或学习数据的前提下，让 iPhone Safari 能可靠播放英语发音，并修复答案页底部图标与文字错位。

## 已确认方案

采用浏览器原生语音增强方案：继续使用 Web Speech API，但不再依赖 Safari 在播放瞬间自动提供默认语音。

## 语音设计

- `BrowserSpeechService` 在生命周期早期读取并缓存系统语音，并监听 `voiceschanged` 更新缓存。
- 每次播放都显式选择目标口音的英语语音；优先精确匹配 `en-US` 或 `en-GB`，否则使用任意英语语音。
- 若系统尚未提供英语语音，不执行一个可能静默失败的空语音，而是返回可理解的中文错误。
- 用户点击“显示答案”“不会”“再听标准发音”或“跟读一次”时，播放调用必须在该用户操作链路中同步发起；不能先等待 IndexedDB 偏好读取后再调用 Safari 语音。
- 语音偏好在训练初始化时加载并缓存。自动朗读继续保持非阻塞，失败不影响显示答案、评分、进度保存或进入下一条。
- 进入下一条、结束训练或组件卸载时继续取消尚未结束的发音，避免上一句英文覆盖下一句中文提示。

## 界面设计

- 两个答案工具按钮保持等宽双列。
- 每个按钮内部使用水平 flex 布局，图标与文字组成一个整体居中，固定间距，图标不压缩。
- 小屏幕保持文字不拆散；按钮至少 44px 高，并保留现有底部安全区。

## 错误处理

- Safari 不支持语音、英语语音尚未加载或播放失败时，在操作区显示简短中文提示。
- 用户仍可继续自评和训练，不弹阻塞对话框，也不请求新的账户或云端权限。

## 验证

- 服务测试覆盖：延迟出现的 voices、明确绑定英语 voice、没有英语 voice 时给出错误、替换与取消仍能正确结束 Promise。
- 训练控制器测试覆盖：自动朗读从已缓存偏好直接发起，不因异步读取丢失用户触发链路。
- 组件/CSS 测试覆盖：两个工具按钮图标文字整体居中、间距与最小触控高度。
- 完整运行单元测试、lint 和生产构建；部署后再用 iPhone Safari 手工点击“再听标准发音”验证真实设备声音。

## 非目标

- 不接入第三方 TTS API。
- 不生成或存储音频文件。
- 不改变句子、分类、复习曲线或训练事件格式。

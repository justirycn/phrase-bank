# 本地 Qwen 生成与人工审查设计

## 目标

把系统句库生成从腾讯云 GitHub Actions 流程迁到用户电脑：安全复用服务器现有 `2026.08.3` 检查点，在本地完成剩余 Qwen 生成与独立审校，随后通过只监听本机的审查页面抽样、搜索和标记问题。只有用户在审查页明确批准后，才允许执行一次最终内容提交和现有生产部署。

## 不在范围内

- 不把 DashScope Key 写入仓库、浏览器存储、命令参数、日志或聊天。
- 不允许审查页直接修改 AI 文本；发现问题后标记并重新生成对应内容，避免人工改写绕过独立审校。
- 不改变个人句子、学习状态、复习计划、账号或云端数据模型。
- 不自动删除服务器检查点，也不自动触发服务器 Qwen 工作流。
- 不在用户批准前创建内容提交或部署。

## 本地秘密与检查点

DashScope 配置存放在项目外：

```text
C:\Users\Administrator\.phrase-bank\qwen-content.env
```

文件只包含 `DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL` 和 `DASHSCOPE_MODEL`。本地命令读取该文件并将值注入当前子进程；不得打印文件内容。启动前必须验证文件位于项目外、是普通文件，并提醒用户限制其 Windows 访问权限。

服务器现有 `.content-agent/checkpoint-2026.08.3.json` 通过明确的单文件下载复制到本地项目的 `.content-agent/`。复制过程不得读取或下载 `/etc/phrase-bank/qwen-content.env`。程序继续验证版本、输入指纹、稳定 ID 和完整元数据；不兼容的检查点必须停止，不能静默从头生成。

## 本地生成流程

新增本地入口负责：

1. 读取项目外的环境文件，但只报告“已配置/未配置”。
2. 验证本地检查点；预计从逻辑进度 `68/120` 继续。
3. 调用现有累计切片协议：完整核心句家庭不可拆分，每个请求最多 10 条，响应必须覆盖该切片的精确 ID 集合。
4. 每个切片格式错误最多重试三次；鉴权、网络策略错误和无进展响应立即停止。
5. 每个完整批次生成后再执行一次独立审核，成功后原子更新检查点。
6. 全部完成后生成候选包与审核报告，但不发布、不提交。

中断后再次运行同一版本必须从最新有效检查点恢复。日志可以显示分类、逻辑进度、切片大小和错误类别，但不能显示 Key、环境文件内容或完整模型响应。

## 本地审查页面

审查页只绑定 `127.0.0.1`，读取本地候选包、审核报告和单独的审查状态文件。它不访问生产 API，不要求登录，也不把候选内容上传到其他服务。

页面提供：

- 总体状态：版本、600 个核心句、2,000 条总内容、独立审核结果和确定性门禁结果。
- 分类、子场景、核心/例句类型筛选和中英文关键词搜索。
- 可复现随机抽样；默认覆盖每个大类和重点工作/供应链/包装场景。
- 中英文并排显示，并显示稳定 ID、分类、子场景及父核心句关系。
- 自动提示重复英文开头、疑似未翻译场景、`regarding xxx` 等占位内容、空文本和明显中英文不一致。
- 每条可标记“通过”或“有问题”，并填写备注；审查状态按稳定 ID 持久化到 `.content-agent/review-2026.08.3.json`。

审查页不允许直接编辑候选文本。标记问题后，“批准发布”保持禁用，并给出需重新生成或处理的 ID 清单。

## 批准与发布

“批准发布”必须满足：

- 候选包和独立审核报告存在且版本一致。
- 报告为 `pass`，数量为 600/2,000，确定性错误为空。
- 审查状态与候选内容哈希一致；候选变化后旧批准自动失效。
- 没有任何“有问题”或未处理的已抽样条目。
- 用户在当前页面明确点击批准，并再次确认版本号。

批准动作只写入带候选哈希和时间的本地批准文件，不直接执行 Git 操作。随后由单独的发布命令验证批准文件、重新运行发布门禁、完整测试、lint、构建和差异检查。全部通过后，只提交版本化 JSON 与 `bundledSystemContent.ts`，非强制推送 `main`，并使用现有部署流程。整个候选版本只产生一个内容提交。

## 错误处理与安全边界

- 本地 Key 缺失或不可读：生成前停止，不回退服务器运行。
- 检查点不兼容：停止并显示原因；不删除、不覆盖原检查点。
- Qwen 或审核失败：保留最后有效检查点，不生成可批准候选。
- 审查发现问题：批准禁用，不提交。
- 候选哈希变化：批准失效，必须重新抽查并批准。
- 发布门禁失败：不提交、不推送、不部署。
- 主分支在审查期间变化：发布前重新同步并拒绝漂移，避免覆盖其他提交。

## 测试与验收

自动化必须覆盖：

- 项目外环境文件加载、缺失、格式错误和日志脱敏。
- 检查点单文件导入、版本/指纹不兼容拒绝和 `68/120` 续跑。
- 本地生成中断/恢复、累计切片、无进展和鉴权失败。
- 审查页面筛选、搜索、随机抽样、问题标记、备注和持久化。
- 自动质量提示的正反例，包括重复开头、漏译场景和占位文本。
- 候选哈希变化导致批准失效；存在问题时不能批准。
- 未批准不能发布；有效批准后只暂存两个发布文件并执行一次非强制推送。
- 本地服务只监听 `127.0.0.1`，不得监听 `0.0.0.0`。

人工验收使用本地候选包，不改学习数据：重点抽查工作、供应链和包装分类，确认英文句式有变化、中文完整翻译场景、例句与核心句关系自然。最终线上验收仍要求生产 JSON、应用首页和部署工作流全部成功。

# Qwen 内容优化与训练优先级设计

## 1. 目标

建立一个手动触发、服务器端运行的 Qwen Plus 内容 Agent，将现有规则化系统句库升级为自然、准确、可长期练习的 2,000 条内容；同时让每天的训练按个人句子、到期复习、系统新句的目标比例选取。

本阶段不在网页中提供实时 AI 生成功能，也不定时调用 Qwen。

## 2. 安全边界

- Qwen 凭据仅从服务器环境变量 `DASHSCOPE_API_KEY` 读取。
- 凭据不得出现在源码、前端资源、Git 历史、浏览器存储、备份、错误消息或日志中。
- 启动时缺少凭据立即失败，并给出不包含凭据的配置提示。
- 已经在聊天中公开的旧凭据视为泄露，必须作废；只允许使用重新创建的凭据。
- Agent 设定单次最大请求数、每次请求超时和有限重试；超过限制立即停止，不发布内容。

## 3. 内容 Agent 架构

Agent 是 Node.js 命令行程序，通过阿里云百炼的 OpenAI 兼容接口调用 `qwen-plus`。运行命令只生成候选发布包，不直接修改浏览器数据库。

内容按六个类别独立处理：日常生活 180 个核心、旅游 100 个核心、工作沟通 120 个核心、商务 100 个核心、供应链 70 个核心、社交 30 个核心。每个核心带 2–3 个有明确关系的发散案例，最终必须精确得到 600 个核心和 2,000 条总内容。

每一类使用两个逻辑阶段：

1. 生成阶段：Qwen 根据类别、子场景、CEFR A2–B2、用户画像和数量约束输出结构化 JSON。
2. 独立审校阶段：使用新的对话上下文检查自然度、中英文一致性、场景实用性、语义重复和不恰当内容，并返回修订结果及通过状态。

六类可以分别请求，但发布是整体原子的：任意一类未完成或未通过，整个候选版本失败，线上旧版本保持不变。

## 4. 确定性校验与发布

Qwen 审校后仍须通过本地不可绕过的质量门：

- JSON Schema、字段枚举和父子关系有效；
- 类别核心配额、600 核心、2,000 总量精确；
- 每个核心恰有 2–3 个连续 `unlockOrder` 案例；
- ID 在同一发布包内唯一且稳定；
- 英文规范化后无完全重复；
- 英文没有孤立小写 `i`、空文本或明显占位符；
- 中文与英文均满足长度上限；
- 所有内容标记统一的新 `contentVersion` 和 `qualityVersion`。

通过后写入候选文件与机器可读报告。发布命令再次校验候选包，将其复制为新的版本化静态文件，并更新应用中的当前内容版本引用。旧版本文件和 IndexedDB 包继续保留以便回滚。

网页启动时沿用现有事务安装机制：保留同 ID 内容的掌握状态、复习记录和解锁状态；安装失败继续使用旧版本并显示非阻断提示。

## 5. 训练调度

标准训练组固定 10 条，目标池互斥并按以下顺序定义：

- 5 条个人句子：`origin=personal`，优先最近添加、未掌握和较弱内容；
- 3 条到期复习：排除已进入个人池的句子，个人或系统均可，按逾期程度和弱项优先；
- 2 条系统新句：从未练习且已解锁的系统核心中选择。

快速组固定 3 条。由于单组无法精确表达 50% / 30% / 20%，选择器根据上海自然日内已经完成的训练事件计算三类累计缺口，优先补足偏离最大的池，使连续多组逐步逼近该比例。

通用规则：

- 自己新增的个人句子进入最高优先级，并参与 5 条个人配额；
- 同一天尽量不重复，除非可用内容不足；
- 某一池不足时按“个人句子 → 到期复习 → 系统内容”的顺序补足，但不制造重复 ID；
- 继续遵守每日个人新句最多 5 条、系统新句最多 3 条的既有上限；
- 抗遗忘的成熟内容仍可通过到期池或补位进入，不会永久消失；
- 选择保持基于日期和 seed 的可复现性，不使用无约束随机数。

## 6. 运维流程

1. 在腾讯云服务器安全配置新的 `DASHSCOPE_API_KEY`。
2. 手动运行候选生成命令；输出六类进度、请求次数、通过数量和不含敏感信息的错误摘要。
3. 检查机器报告为通过后运行发布命令。
4. 提交新的版本化内容文件和版本引用，走现有 GitHub Actions 测试与部署。
5. 公网验证新内容文件可访问、网页完成安装、个人内容和学习状态未丢失。

首版不提供定时任务；只有人工手动触发才产生 Qwen 费用。

## 7. 错误处理

- 认证失败、限流、网络超时、非 JSON 响应或审校不通过：有限重试后停止该次运行。
- 进程中断：保留临时候选与进度记录，但它们不能被网页安装；重新运行可安全覆盖候选。
- 候选质量门失败：生成报告并退出非零状态，不改变正式内容。
- 发布后客户端安装失败：继续使用旧版本，允许下一次刷新重试。

## 8. 测试与验收

- 使用伪造 HTTP 服务测试请求格式、超时、重试、认证头和敏感信息不进入输出；测试不调用真实 Qwen、不使用真实 Key。
- 使用固定 Qwen 响应测试六类聚合、独立审校失败、结构校验失败和原子发布。
- 回归测试正式内容包的 600/2,000、配额、父子关系、重复和版本一致性。
- 选择器测试标准组精确 5/3/2、快速组按当日缺口轮转、每日新句上限、池不足补位、去重和不修改输入。
- 仓储测试验证新版本安装保留学习状态并可回滚。
- 全量测试、代码检查和生产构建全部通过后才允许部署。

## 9. 非目标

- 不把 Qwen Key 放进网页或 GitHub。
- 不在用户每次添加句子时实时调用 Qwen。
- 不做自动定时更新。
- 不引入账号、多设备同步或云端用户数据。
- 不允许未完成的类别或仅通过 Qwen 自评的内容直接上线。

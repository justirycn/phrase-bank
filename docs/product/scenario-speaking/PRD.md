## 1. 产品决定

在现有首页增加「场景口语」入口。用户选择一个真实情境，用约 8 分钟完成「听懂 → 跟读 → 自己说 → 留下待练表达」。

学习目标：把句库中认识的表达组合成能在生活或外贸沟通中说出来的一段话。单次默认 5 句，最后尝试表达 30–60 秒，允许更短，不用凑时长。

首版建议先做「固定场景 + 参考发音 + 临时录音回听 + 中文提纲表达 + 自评」。AI 生成个人场景、语音转写反馈和自由角色对话分阶段加入。

核心判断：能否让用户更愿意开口，并在第二次练同一情境时减少对英文提示的依赖。完成跟读不等于独立表达，独立表达自评也不等于现有句库的「三日掌握」。

## 2. 背景与现有能力

用户已经在积累日常高频语言块，重视覆盖面与去重，同时需要站在「中国供货方 / 贸易商」立场与海外客户沟通。外贸方向涉及产品、报价、寄样、交期与问题处理，不是企业内部供应链管理培训。

| 本次从代码确认的能力 | 对新功能的意义 |
| --- | --- |
| 每日任务、主动复习、自主学习、个人句库 | 保持原有入口；场景训练作为可选练习 |
| 系统句子带分类、意图、等级等字段 | 可建立场景与语言块的关联，避免重新堆砌句子 |
| 浏览器发音服务，支持美式 / 英式偏好 | 可复用发音基础；实际音色和可用性取决于浏览器 |
| 临时录音服务与控制器能力 | 可作为录音基础；当前复习界面没有可见的开始录音入口，需要新训练页接入 |
| 云端版本校验、冲突处理与诊断接口 | 复用基础设施；场景会话仍需新增数据、恢复与兼容设计 |

## 3. 用户故事与边界

- 日常交流：我想解释退货寄出后还没收到退款，能把事情讲清楚，并问下一步怎么处理。
- 外贸沟通：我想回答海外客户的寄样问题，连贯说明样品、费用、寄出条件和收件信息。
- 零碎练习：我只有几分钟，想继续上次场景；在公共场所也能只听或轻声练习。
- 自我检查：我想听自己的录音，找出卡住的 1–3 个表达，下次重点练。

| 范围 | 首版 V1 | 后续版本 |
| --- | --- | --- |
| 内容 | 12 个编辑校验的固定场景，日常 8 个、外贸 4 个 | 用户输入「我想说什么」生成个人场景 |
| 训练 | 单句跟读、临时录音、回听、提纲表达、自评 | 预设多轮对话，再到 AI 自由角色对话 |
| 反馈 | 是否用提示、是否完成尝试、用户自评、重点表达 | 转写与表达建议，必要时接专门发音评测 |
| 句库 | 优先关联已有句子；手选待练表达，新增前确认去重 | 基于用户输出提出候选表达 |
| 同步 | 场景、步骤、自评、提示记录、待练清单 | 可选录音存档与跨设备回听 |

V1 不设置真人水平分数、自动判定口语掌握、每日强制口语任务、排行榜、连续打卡惩罚、视频素材平台或大规模音标课程。避免首版入口和内容负担过大。

## 4. 入口与信息结构

首页保持「继续今日任务」的主行动。在现有自主学习入口后、周总结前放置一行「场景口语」，副文案「把学过的句子，连起来说 · 约 8 分钟」。作为次级入口，使用浅底、细边框、麦克风图标。

无需先完成每日任务即可进入，不要求拥有已学句子。新用户使用基础场景；老用户看到包含熟悉表达的推荐。暂停中的每日复习不被新场景覆盖。

有未完成场景时显示「继续：寄样与确认交期 · 跟读 2 / 5」，进入原步骤；同一入口下仍可选择其他场景。

页面结构：

1. 场景列表：日常交流 / 外贸沟通两个分组；推荐一项，其他以简洁列表展示。
2. 任务预览：说明双方角色、沟通目标、预计时长、3 个要点。
3. 训练页面：听懂、跟读、自己说三个阶段。
4. 回听与小结：完成方式、自评、待练表达、再练一次或返回首页。

首版不新增底部一级导航。进入训练后隐藏全局底栏，顶部返回可暂停；返回时停止音频和录音，不依赖等待云端保存才能离开页面。

## 5. 首版完整流程

| 步骤 | 用户看到什么 | 主行动 | 结果 |
| --- | --- | --- | --- |
| 选场景 | 标题、目标、约 8 分钟、基础 / 进阶标记 | 选择场景 | 打开目标预览 |
| 任务预览 | 角色、3 个沟通要点、5 句参考表达 | 开始练习 | 建立独立场景会话 |
| 听懂 | 英文与中文含义；一次聚焦一条 | 听参考发音 | 可重复，也可直接进入跟读 |
| 跟读 | 英文、中文、可选的一条节奏提示 | 录下我的跟读 | 停止后能回听、重录或下一句 |
| 自己说 | 仅中文情境与 3 个要点，英文默认收起 | 开始录音 | 尝试 30–60 秒连贯表达 |
| 回听自评 | 本次录音、提示使用记录、3 档自评 | 完成本次练习 | 保存结果并打开小结 |
| 小结 | 本次完成方式、待练表达选择 | 保存并回首页 | 记录状态明确；允许再练同一场景 |

默认每个场景 5 句，内容允许 4–6 句。用户可跳过已熟悉的跟读步骤，但跳过不计入完成跟读数。只听完不记为完成口语表达。

### 5.1 听懂与跟读

- 发音必须由点击触发；进入页面、切换句子、恢复会话时不突然播放。
- 遵循现有口音偏好，提供 0.8× / 1.0× 两档速度；速度控制需扩展现有服务。
- 每次只突出一条英文；中文可收起，长句允许自然滚动，不扩大字体挤出屏幕。
- 主按钮依状态变为「录下我的跟读 → 停止录音 → 下一句」。已有录音时，次操作为「听我的录音」「重录」。
- 点击「不方便录音，直接跟读」后，完成动作由用户确认，记录为未录音练习，不伪装成已录音。
- 录音期间关闭参考音频，播放参考音频前先停止录音，避免同时占用声音通道。
- 录音启动超过 10 秒仍没有结果，提供取消和无录音练习；迟到的授权结果不得重新启动录音。

### 5.2 自己说与提示规则

页面只保留「这次说清哪 3 件事」、录音动作和求助入口。30–60 秒是建议，非倒计时考试。录音最长 90 秒，到时自动停止并保留有效内容。

「看一句提示」展开与当前要点相关的一句英文。继续展开可看到其余参考；任何英文参考或参考发音的使用，均计入当前表达尝试的提示标记。

| 自评选项 | 无提示且已尝试 | 本次使用过提示 |
| --- | --- | --- |
| 还说不出来 | 可选 | 可选 |
| 能说一些，还会卡 | 可选 | 可选 |
| 能独立说清楚 | 可选，自评不代表系统认证 | 灰色禁用，旁注明「本次用过提示，可再试一次」 |

不能通过关闭提示、返回上一页、刷新或切换设备清除提示记录。点击「重新挑战」才创建新的表达尝试：关闭英文、清空当前尝试计时与录音，保留上一尝试的提示使用历史。

新尝试可以自评独立完成，但不自动提升对应句子的 SRS 等级。无录音方式需主动确认「我已开口尝试」，再进行自评；仅点开页面不能获得完成记录。

### 5.3 回听、小结与待练表达

小结显示「本次已完成 / 仅完成跟读 / 本次已暂停」「录音或无录音练习」「本次使用过提示」「你的自评」。不显示未经验证的流利度、准确率或发音分。

用户可以从场景表达中手选最多 3 条「下次重点练」，默认不勾选。已有关联句子的只保存引用；独立场景文本若要变成个人句子，先展示中英预览、来源和重复候选，用户确认后才加入。

「下次重点练」保存在场景模块的待练清单，下次进入该模块时优先推荐相关场景。V1 不改动现有到期复习队列、今日答对数或三日掌握规则，避免一次场景练习重复计分。

## 6. 内容设计：覆盖广但不堆重复

### 6.1 首批 12 个场景

| 方向 | 场景 | 要完成的交流目的 |
| --- | --- | --- |
| 日常 | 和新认识的人聊几句 | 自我介绍、接话、自然结束 |
| 日常 | 约时间与临时改期 | 提议、解释冲突、确认新时间 |
| 日常 | 没听清时继续对话 | 请求重复、确认理解、继续回应 |
| 日常 | 点餐与表达偏好 | 说明需求、询问替换、确认订单 |
| 日常 | 问路与确认交通 | 说明目的地、问换乘、确认方向 |
| 日常 | 退货与查询退款 | 说明已寄出、核对记录、询问处理 |
| 日常 | 描述一个遇到的问题 | 描述现象、说明影响、寻求帮助 |
| 日常 | 礼貌拒绝与提出替代 | 表达限制、保持友好、提出选择 |
| 外贸 | 介绍产品与供货能力 | 介绍角色、产品范围、确认客户需求 |
| 外贸 | 报价与确认起订量 | 确认规格数量、解释价格、约定下一步 |
| 外贸 | 寄样与确认交期 | 样品需求、寄出条件、收件信息 |
| 外贸 | 处理延误与质量反馈 | 确认问题、收集证据、说明后续处理 |

这只是第一批练习，不代表完整覆盖。后续按「沟通目的 × 情境 × 难度」扩充，检查意图覆盖，而不是只统计句子总数。

### 6.2 内容规则

- 以 A2–B1 的清晰常用口语为主要难度，允许后续增加 B2。等级是内容标签，不是对用户能力的测评。
- 同一场景围绕一个交流结果，句子间有上下文关系，不随机拼接无关句子。
- 优先引用现有合适的语言块；为了连贯可以增加桥接句，但桥接句不自动复制进用户句库。
- 以「沟通意图」归并近义表达，一个功能先给一个推荐说法；其他说法在后续阶段按需展开。
- 同一句在不同场景合理复现是迁移训练；共享同一个 phraseId，避免产生多个近重复学习项目。
- 场景内最多引入 1–2 个核心新表达是编辑目标，不是硬凑已学比例。相关已学句不足时明确说明「含新表达」，不伪报熟悉度。
- 外贸语料以中国供货方视角写，避免把所有用户写成工厂、编造认证、保证库存或承诺具体运输时效。
- 所有价格、数量、交期、产品名称为示例变量。界面应提示按实际情况调整，不把练习文本作为真实交易承诺。

### 6.3 完整样例：寄样与确认交期

角色：你是中国供货方，对方是询问样品的海外客户。

目标：确认样品需求，解释寄出条件，并获取收件信息。
任务要点：① 确认样品与数量；② 说明付款后寄出；③ 索取收件信息。

| 参考表达 | 中文含义 |
| --- | --- |
| We can send you a sample before you place an order. | 你下单之前，我们可以先寄一个样品。 |
| Which model would you like to try, and how many samples do you need? | 你想试哪个型号，需要几个样品？ |
| We’ll ship the samples once we receive the sample payment. | 收到样品费后，我们会安排寄出。 |
| Could you send me the delivery address and a contact number? | 可以把收件地址和联系电话发给我吗？ |
| I’ll send you the tracking number once the package is on its way. | 包裹寄出后，我会把运单号发给你。 |

参考仅是一种自然说法，允许用户用其他正确表达。模拟业务条件：本例收取样品费；不暗示每项实际业务都如此。

首轮 UI 概念中可能显示的多轮客户问句属于 V1.1 的预设对话方向，例如 “When can you send the samples?”；该台词不是实时 AI 生成或真实客户消息。

## 7. UI 规范与方向稿

采用现有颜色：米白 `#fbf8f0`、纸白 `#fffdf8`、主文字深绿 `#0b4a3a`、次文字 `#29594c`、提示橙 `#d66f3f`、辅助文字 `#737a76`、分隔线 `#ddd9cf`。

保留简洁、温和、有留白的学习感。段落优先靠间距与细分隔线区分，避免一层套一层卡片。图标沿用现有 Phosphor 风格。正常正文 15–17px，中文标题 26–32px；英语练习句约 24–30px，长句缩小字号并允许滚动。

三张独立概念稿探索不同的信息重心，不是三个已实现页面，也不要求首版全部加入。可在[设计评审页](README.md)查看原图：

- 逐句引导：一屏一句，核心是听参考和跟读，适合首版学习阶段。
- 提纲表达：突出需要说清的事情，英文隐藏，适合首版「自己说」阶段。
- 情景对话：突出对方问句和自己的回应，适合 V1.1 预设对话阶段，后续可承接 AI 对话。

推荐产品组合：首版采用逐句引导的学习结构，再进入提纲表达；多轮对话放到基本流程稳定之后。图片只用于讨论排版与体验，以本文的范围和状态规则为实现依据。

### 7.1 手机和桌面适配

- 训练容器以动态视口高度计算，顶部步骤、可滚动正文、底部操作区分离；操作区为自身布局的一部分。
- 底部预留安全区；正文需为操作区留足空间。避免以固定大字和固定底栏共同挤压正文。
- 375×667 小屏允许正文滚动，主要操作始终可到达；长中英文不得横向溢出。
- 390×844 为主要设计尺寸；同时验收 768×1024、1366×768 与桌面 200% 缩放。
- 桌面跟读正文最大宽度约 640px。宽屏提纲表达可左右分栏，左侧任务与要点，右侧录音 / 回听；窄屏顺序折叠。
- 训练页不展示底部主导航。关闭、返回、提示、录音按钮触摸区域至少 44×44px；主按钮至少 48px 高。
- 禁用选项同时用状态和说明文案表达，不能只靠颜色。键盘焦点可见，录音状态提供文本提示。

## 8. 会话、保存与故障体验

### 8.1 防止重复跳转与卡住

业务状态与保存状态分别管理。训练状态建议为 `preview → listen → shadow → speak → reflect → complete`；保存状态独立为 `idle / saving / synced / failed`。一次用户动作最多产生一次步骤推进。

完成由用户明确提交触发，保存成功不再次触发「完成」或自动进入新组。完成页只有明确按钮可开启下一次训练，不在初始化或刷新结果后自动来回跳转。

### 8.2 保存与离线

优先将场景检查点写入独立的本地草稿，再尝试云端保存。此草稿能力需要新增；现有云端写失败回滚机制不能直接当作离线会话恢复功能。

- 云端保存超过 8 秒，结束等待状态并展示「同步未完成，可重试；本机草稿已保存」，前提是本地写入确实成功。
- 本地也失败则明确显示「尚未保存」，不展示已保存或云端同步完成；当前页面仍可回听和继续。
- 请求超时后即使迟到成功，重试仍使用相同操作标识，不重复增加完成次数或待练条目。
- 无网时已缓存场景可练；没缓存的明确显示暂不可用。离线草稿标注本机待同步，不承诺另一台设备可恢复。
- 场景完成与加入个人句库是独立动作；添加失败不能把整个练习重新变成未完成。

### 8.3 多设备与录音

- 云端同步场景、版本、步骤、提示历史、自评和待练清单。恢复时明确显示上次步骤。
- 同一会话在另一设备继续时需取得新的会话编辑版本；旧设备不得覆盖新步骤。被接管的设备可另开新会话继续，不混合两份当前步骤。
- 场景模板升级不改写进行中的内容；会话固定内容版本或内容快照。
- 临时录音默认不上传、不跨设备保存；离开会话或刷新后不可恢复。界面在首次录音前说明，切设备只恢复文字进度。
- 录音被来电、锁屏、切后台中断时停止计时并尽可能保留有效片段。回到页面不自动重新录音；录音失败允许直接练习。
- 拒绝麦克风权限不阻塞任务，可继续听音频和无录音表达，不反复弹权限请求。

## 9. 数据与接入建议

这是实现建议，需在开发时结合现有备份与同步契约细化，不应直接把场景会话塞入现有随机复习会话。

| 数据 | 最少需要记录 |
| --- | --- |
| 场景模板 | id、版本、日常/外贸、难度、双方角色、目标、中文提纲、排序后的参考表达、关联 phraseId |
| 场景会话 | id、用户、模板版本或快照、阶段、句索引、开始/更新时间、完成时间、编辑版本、当前设备标识 |
| 表达尝试 | attemptId、会话、起止时间、录音/无录音、是否使用提示、提示条目、自评、被中断状态 |
| 待练清单 | 场景/句子引用或临时文本、来源 attemptId、添加时间、处理状态 |
| 本地草稿 | 会话快照、待同步操作标识、最后云端版本、同步状态；不含音频二进制 |

扩展点：新增场景模板、选择逻辑、会话控制器与屏幕；复用发音服务、录音服务、图标、账号和诊断通道。备份格式需版本化升级、支持旧数据导入，并定义旧客户端不能覆盖新字段的行为。

不从现有 `TrainingEvent` 直接派生场景完成统计，不把新模块的一次自评写成多句 `good`。优先保证旧学习流程的数据含义稳定。

诊断仅包含预定义故障代码、页面、版本、网络与耗时范围；不发送录音、原文、客户信息或自由输入。新增记录建议覆盖录音启动失败、录音中断、发音失败、会话保存超时、恢复失败、重复完成被拦截。

## 10. AI 能力与成本路线

| 阶段 | 能力 | 上线前提 |
| --- | --- | --- |
| V1 | 固定场景、浏览器参考发音、临时录音、自评 | 核心流程和恢复验证通过；运行期不新增模型调用 |
| V1.1 | 预设 2–3 轮角色对话、个人场景文本生成 | 先验证固定对话有用；生成内容需预览、校正后保存 |
| V2 | 录音转写与表达反馈，最多聚焦 3 个问题 | 明确音频发送对象、保存期限、预算与真实音频准确性 |
| V3 | 动态角色扮演、按薄弱点追问 | 控制费用与延迟，验证移动端连续对话体验 |

V1.1 的个人生成流程：输入中文需求 → 生成 4–6 句自然英语和中文提纲 → 用户核对事实与业务条件 → 保存为个人场景。失败保留输入，明确重试，不静默后台循环产生费用。

沿用已配置 Qwen 的方向，但本次设计不调用付费生成。开发 AI 版本时再根据实际模型与音频服务核算费用，设置每日调用上限、去重、结果缓存和超额停用。文本模型不能直接替代音素级发音评估；转写文字也不能证明发音准确。

AI 反馈优先回答「意思有没有表达出来、哪一句更自然、下一次练什么」，不把接近母语口音设成唯一目标，也不机械要求和参考答案逐字一致。

## 11. 验收标准

以下是开发后的验收要求，本次没有执行这些功能测试，不能把它们当作已通过结果。

| 编号 | 操作 / 条件 | 通过标准 |
| --- | --- | --- |
| AC-01 | 从首页进入；今日任务未完成 | 可开始场景，原任务和句库进度不变 |
| AC-02 | 选择寄样场景完成整轮 | 可经历听懂、跟读、自己说、小结；不自动刷新或重建会话 |
| AC-03 | 看过英文提示后自评 | 「能独立说清楚」灰色禁用；事件处理也拒绝绕过；重新挑战可建立新尝试 |
| AC-04 | 用提示后刷新或跨设备继续 | 提示历史保留，最高档不被意外解锁 |
| AC-05 | 拒绝麦克风、授权迟到、录音中断 | 可取消和无录音练习，无永久加载，离开后不残留录音 |
| AC-06 | 播放参考、录音、回听互相切换 | 无叠音、重复录音或残留麦克风占用 |
| AC-07 | 保存请求超时或断网 | 最迟 8 秒显示可操作状态；只有确实写入本地才能称草稿已保存 |
| AC-08 | 连点完成 / 迟到响应 / 再次重试 | 同一会话只完成一次，小结停留稳定，可正常返回或再练 |
| AC-09 | A 设备练到跟读第 3 句，B 接续后 A 再保存 | 已同步检查点可恢复，旧写入不能回退新进度；录音不可同步有明确说明 |
| AC-10 | 已有句子再次选择加入 | 已关联的不重复创建；未关联文本先给重复候选和预览 |
| AC-11 | 查看提示 / 跟读 / 自评独立完成 | 不增加原有今日答对、三日掌握或自动修改 SRS |
| AC-12 | 375×667、390×844、平板、桌面和 200% 缩放 | 无横向溢出，长文本可读，按钮可到达，正文不被底部覆盖 |
| AC-13 | 内容升级或旧备份导入 | 进行中会话内容稳定，旧句库、进度与偏好不丢失 |
| AC-14 | 无音频能力、无已学句、无匹配内容 | 有真实可用的降级或空状态，不显示虚假成功 |

浏览器验证分两层：自动化覆盖桌面 Chromium 和移动尺寸 WebKit 的步骤、保存、提示规则；真实 iPhone Safari 验证权限弹窗、播音/录音切换、锁屏恢复、地址栏变化和小屏底部。自动化 WebKit 通过不等于真机 Safari 已验证。

## 12. 试用与交付节奏

先完成 1 个日常场景和 1 个外贸场景，把全流程与异常状态跑通，再扩充到首批 12 个。每一步交付前验证现有每日任务和复习仍正常。

建议个人试用 7 天，观察：开始到完成的比例、实际开口尝试次数、同场景第二次的提示依赖、自评变化、想复用的表达，以及「这句话是否真的用得上」。这些是产品观察指标，不作自动能力评级。

建议继续投入 AI 的判断条件：用户能顺利完成至少 3 次练习，愿意重复同一场景，并能指出现有自评最想补充的反馈。若主要问题仍是步骤繁琐或不想录音，先简化流程。

本轮交付：本 PRD、三张 UI 概念图、视觉生成提示记录。当前待评审的是功能范围和界面方向；确认方向后再做可点击原型与开发。
